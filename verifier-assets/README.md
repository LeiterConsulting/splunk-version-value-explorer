## Wrapper contract

Run `scripts/verify_export_attestation.py --gh ABSOLUTE_PINNED_BINARY --root verifier-assets/trusted-root.jsonl --archive ORIGINAL.zip --bundle ORIGINAL_BUNDLE.json --expected INDEPENDENT_CONTEXT.json`.

The expected context must be generated by trusted coordinator logic from fresh GitHub exact-attempt/service facts and independent original bytes, not supplied by an HTTP caller or copied from the attestation predicate. A local CLI argument is not an authentication mechanism. The wrapper never accepts saved verifier output as an authority input; it starts the pinned executable itself, then enforces certificate extensions and statement binding. It recomputes archive and complete payload manifest hashes with the bounded ZIP inspector.

The signature subprocess has 120-second wall/90-second CPU, 4 GiB virtual memory, Go 256 MiB soft heap target, 1 MiB stdout and 128 KiB stderr caps. Its process group is killed on timeout/overflow. The CLI parent sets a 600-second whole-run alarm, 400-second CPU limit and 768 MiB address-space soft limit (4 GiB hard ceiling permits the separate Go child's arena). This covers hashing/inspection as well as signature verification. The archive inspector separately has 300-second checks, a bounded central directory and streaming 2 GiB archive/4 GiB expanded/20,000-member policy. Python callers importing `verify` rather than running the CLI must provide equivalent whole-process resource limits. No inherited credentials, gh config or proxies are passed to offline verification. Root and bundle are copied to a private directory. Files/tool paths and expected policy are trusted local inputs; hostile concurrent writers are outside this boundary and require immutable storage/sandbox integration.

Successful output means signature and exact certificate attempt plus signed upload assertion match independently expected evidence. It does not establish service snapshot authenticity by itself, semantic approval, durable admission, database integrity or deployment. Admission remains held and productionActionAllowed false.

## Source-reviewed field semantics

GitHub CLI v2.104.0 `pkg/cmd/attestation/verification/sigstore.go` returns `verificationResult.signature.certificate`, `verifiedTimestamps`, and `statement`. Its dependency `github.com/sigstore/sigstore-go v1.4.0` embeds `Extensions` in certificate `Summary`, so extensions are flattened camelCase fields, not a nested `extensions` object. Required `runInvocationURI` is certificate-bound, not taken from custom predicate. Missing exact run/attempt, owner/repository IDs, push trigger, main ref, workflow/source digest or hosted-runner extension holds.
