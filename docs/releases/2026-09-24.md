# September 24, 2026 — Observability expansion and Cloud guidance corrections

Splunk revised the September 2026 Observability Cloud timeline on September 23 with customer-visible APM, RUM, Synthetics, integrated-logs, and Cloud-connected onboarding changes. Splunk also published OpenTelemetry .NET instrumentation 1.16.0 with a new installer-verification prerequisite. Version Compass now includes those records in the existing September milestone without inventing a new SaaS version or Cloud Platform route.

## Customer-facing changes

- APM now describes delegated business-transaction and endpoint-rule management through a custom role, plus enhanced endpoint and instance panels with RED metrics and representative error and latency traces.
- RUM adds AI-assisted linear and nonlinear Business Journeys, attribute classification, links to Tag Spotlight and Session Search, and separate base-page-load versus route-change latency.
- Synthetics records the two private-runner changes exactly as published: version 1.44.0 updates Chrome and Chromium to 151 and refreshes security/maintenance components; version 1.39.0 restores NTLM authentication for HTTP tests.
- Observability Logs is recorded as a cloud-only integrated experience that uses a Splunk Cloud stack, Unified Identity, centralized RBAC, data-level access control, and OpenTelemetry or Data Manager onboarding.
- The free-edition flow is scoped to a Splunk Cloud Platform 10.6 environment, the Discover Splunk Observability Cloud app, and an `admin` or `sc_admin` role. It can enumerate paired indexes for OpenTelemetry-compliant logs.
- Splunk OpenTelemetry .NET 1.16.0 adds immutable release assets and artifact-attestation verification. Its PowerShell installation/update commands and shell installer require GitHub CLI by default; the documented skip flags explicitly bypass verification. The release also exposes snapshot-selection probability in effective configuration.

## Affected products, routes, and boundaries

The changes apply to Splunk Observability Cloud routes ending at `Sep 2026` in either Enterprise or Cloud host context. They add capabilities, five route-specific technical-change records, and readiness checks for roles, private-runner versions, .NET installer verification, Cloud pairing, identity, data access, onboarding, and trial eligibility.

No Splunk Enterprise, Enterprise-to-Cloud, Enterprise Security, ITSI, SCMA, compatibility-gate, lifecycle-policy, WebMCP schema, or ES editions claim changes. The current Cloud release-note root and service details still publish the 10.5 line, paired with ES 8.6 and ITSI 5.0. The Observability timeline's 10.6 reference is therefore a scoped integration prerequisite, not proof of a generally selectable Cloud 10.6 release, region, entitlement, premium-app pairing, or rollout schedule.

## Guidance audit corrections

The same-day guidance audit corrected four existing scope statements without adding a release identifier:

- Targeted app installation is no longer described as reaching general availability. Splunk documents it for Victoria Experience with `sc_admin`, cloud-provider, and stack-version prerequisites: AWS requires 10.2.2510 or higher, while GCP and Azure require 10.5.2605.0 or higher.
- Scheduled-search frequency limits and the Cisco Cloud Control integration now retain Splunk's Controlled Availability label instead of presenting those capabilities as universally available.
- The password readiness action now describes restrictive-by-default credential ACLs in the Credentials page. It no longer mischaracterizes the change as a password network allow-list control.
- The Node.js 4.11 readiness action now attributes stable HTTP and database semantic conventions directly to the Node.js instrumentation release. Kubernetes-chart packaging remains a separate, independently cited component fact.

These corrections affect the Cloud Platform route ending at 10.5.2605 and Observability routes ending at September 2026. They improve availability and prerequisite accuracy; they do not change platform pairings, lifecycle dates, upgrade paths, or breaking-change severity.

No new breaking-change flag is asserted for the September 23 SaaS additions. The .NET 1.16 installer prerequisite is separately marked as a potential rollout blocker because installation or update can stop when GitHub CLI is unavailable; bypassing verification is an explicit security exception, not the default readiness path. Collector 0.161.0, Kubernetes chart 0.161.0, Node.js 4.11.0, and Browser RUM 3.1 remain the current component versions; only the Node.js readiness action's source attribution changed.
