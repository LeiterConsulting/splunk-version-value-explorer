# September 22, 2026

## Summary

Version Compass added Splunk OpenTelemetry Collector for Kubernetes chart 0.161.0, published September 21, 2026. The chart now packages Splunk OpenTelemetry Collector 0.161.0, so chart users inherit the Collector line's Kubernetes semantic-convention and kubelet CPU-calculation changes without separately overriding the image.

## Affected products and routes

- Splunk Observability Cloud routes ending at the September 2026 milestone, in both Splunk Enterprise and Splunk Cloud Platform host context.
- Customer-managed Kubernetes collection and operator prerequisites only. No rolling Observability Cloud SaaS milestone, Splunk platform release, Enterprise Security version, ITSI version, migration route, or compatibility gate changed.

## Customer-facing impact

The Observability route no longer describes Kubernetes chart users as remaining on Collector 0.160.1. It now identifies chart 0.161.0's packaged Collector, Target Allocator, and Operator baselines and makes the chart's migration work explicit.

## Compatibility, readiness, and breaking-change implications

- Chart-generated Kubernetes label and annotation attributes move to stable singular semantic-convention names, and container image metadata uses `container.image.tags`.
- Kubelet CPU usage and utilization use scrape-to-scrape rates by default and are absent on the first scrape after startup, requiring baseline and detector review.
- The chart updates Target Allocator from 0.158.0 to 0.159.0 and Operator from 0.122.1 to 0.123.0.
- `featureGates.useLightPrometheusReceiver` is deprecated, not removed. Version Compass recommends validating the standard Prometheus receiver with the gate set to `false` before a future release removes the light-receiver path.
- Standalone Collector 0.161.0 and chart 0.161.0 are still separate release artifacts, even though their Collector baseline is now aligned.
