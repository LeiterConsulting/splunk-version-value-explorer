# September 30, 2026 — Splunk Enterprise 10.4.4 maintenance target

## Plain-language summary

Splunk Enterprise 10.4.4 was published on September 29, 2026. Version Compass now identifies 10.4.4 as the current maintenance target for customer-managed Enterprise 10.4 routes, including Heavy Forwarder guidance. The release-line selector remains 10.4: this patch update does not create another journey or imply a new Cloud Platform version.

The previously documented safety rule is preserved separately. Splunk continues to direct customers away from 10.4.2 because acknowledged `tcpout` forwarding can block on a receiving heavy forwarder or indexer, and 10.4.3 remains the documented minimum that fixes that issue. The 10.4.4 fixed-issues page did not enumerate customer-actionable fixes when checked, so the guide does not invent features, security coverage or resolved defects for 10.4.4.

## Affected products and routes

- **Splunk Enterprise:** routes ending at 10.4 now say to target 10.4.4 for new upgrade work while retaining the 10.4.3 minimum and the 10.4.2 exclusion.
- **Splunk Forwarders:** Universal and Heavy Forwarder routes ending at 10.4 now distinguish the current 10.4.4 maintenance release from the acknowledged-forwarding safety floor. Receiver compatibility, OS/architecture support and upgrade support remain separate claims.
- **Splunk Cloud Platform, Enterprise Security and ITSI:** no route or pairing change. Current Cloud service details continue to publish Cloud 10.5 with ES 8.6 and ITSI 5.0; the customer-managed compatibility matrix remains separate.
- **Enterprise-to-Cloud migration and Observability Cloud:** no factual route change. The September Observability timeline still ends with September 23 entries, and the maintained Collector, Kubernetes chart, .NET, Node.js, Java, Python and Browser RUM release streams are unchanged.

## Customer-facing impact

Customers planning a 10.4 Enterprise or forwarding-chain upgrade receive a current patch target without losing the exact reason that 10.4.2 must be avoided. Existing shared URLs remain valid because the selectable release identifier stays at 10.4. Cloud-managed stacks do not inherit this customer-managed patch recommendation.
