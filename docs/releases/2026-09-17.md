# September 17, 2026

## Summary

Version Compass corrected the Splunk Cloud Platform 10.4 technical scope, completed the Splunk Enterprise 10.4 runtime and KV Store transitions, and made the Enterprise Security 8.7 edition and enablement boundaries explicit.

## What changed

### Splunk Enterprise 10.4

- Added the documented Python transition from the 10.2 split-runtime state to Python 3.13 as the default interpreter with Python 3.9 available as a fallback.
- Added the customer-managed KV Store transition from the required MongoDB 7 pre-upgrade baseline to MongoDB 8.0, including the supported bridge-release requirement for older engines.

### Splunk Cloud Platform 10.4

- Removed a jQuery record that was inferred from Enterprise guidance rather than documented in the Cloud 10.4 release notes.
- Added the Cloud-documented Python 3.13 default and TLS 1.0/1.1 default-disable transitions, with customer actions limited to private apps and customer-managed integration endpoints.
- Made AI Canvas beta access and onboarding requirements explicit.

### Enterprise Security 8.7

- Added exact edition boundaries: AI SOC Analyst and Connector Builder Agent are Premier features requiring Splunk enablement; Automation Builder is available in Essentials and Premier; Enterprise Security on MCP and Detection Builder are documented for Essentials and are also included in Premier.

### Documentation and links

- Repaired the Enterprise upgrade-path link in the Enterprise-to-Cloud source map.
- Updated the on-site and printable-report review date to September 17, 2026.
- No selector layout or screenshots changed.

## Customer-facing impact

Enterprise routes now expose the full Python and KV Store state changes at 10.4. Cloud routes no longer inherit an Enterprise-only technical claim and instead show only Cloud-documented customer responsibilities. ES 8.7 readers can distinguish edition and enablement prerequisites before planning adoption.

## Compatibility, readiness, and breaking-change implications

- The Enterprise platform-line route remains unchanged: older 9.x sources still use a supported 10.0 or 10.2 bridge before 10.4.
- The ES and ITSI simplified Enterprise compatibility gates remain unchanged because the official patch-level matrix did not change.
- The current Cloud service pairing remains Cloud 10.5 with ES 8.6 and ITSI 5.0; availability remains Splunk-managed and stack-, region-, entitlement-, and schedule-dependent.
- No Observability Cloud or customer-managed OpenTelemetry version changed in this audit.

## Held for human review

- Splunk's Enterprise 10.4 **READ THIS FIRST** page says TLS 1.0 and 1.1 support is completely removed, while the Enterprise 10.4 **What's New** page says the protocols are disabled by default but remain available for migration. Version Compass continues to follow the higher-priority upgrade warning and did not publish a speculative reconciliation. The Cloud route uses the separate Cloud 10.4 wording, which explicitly says disabled by default.
