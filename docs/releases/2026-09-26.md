# September 26, 2026 — Enterprise 10.4 maintenance target and release-watch outcome

Splunk's Enterprise 10.4.3 fixed-issues guidance advises customers not to target 10.4.2. Version Compass now exposes 10.4.3 or later as a required maintenance target on routes that reach Enterprise 10.4.

## Customer-facing change

- Added a required technical-change record and readiness blocker for the Enterprise 10.4 maintenance line.
- Splunk documents that 10.4.2 can block `tcpout` forwarding pipelines when `useACK=true` is enabled on a receiving heavy forwarder or indexer. The route now directs customers to 10.4.3 or later and calls for acknowledged-forwarding validation before production rollout.
- The visible destination remains the 10.4 release line. This exact patch requirement does not create a separate selector and is not generalized to Splunk-managed Cloud stacks.

## Compatibility, readiness, and breaking-change implications

The change affects customer-managed Splunk Enterprise routes ending at 10.4. It is presented as a blocker because a documented forwarding failure can interrupt data delivery. Existing 10.4 KV Store, TLS, certificate, service-identity, application and dashboard requirements remain unchanged.

The current compatibility matrix includes a 10.6.x row, but no corresponding Enterprise or Cloud release-note destination or current Cloud service-details pairing was found. Version Compass therefore does not publish a 10.6 Platform route from that row alone. The current Cloud service-details table continues to identify Cloud 10.5, Enterprise Security 8.6 and ITSI 5.0; Cloud premium-app availability remains stack-, region-, entitlement- and schedule-dependent.

No Enterprise-to-Cloud route, ES/ITSI platform gate, ES Editions capability, cloud-environment record, Observability milestone, customer-managed OpenTelemetry component, WebMCP schema, lifecycle-policy date or navigation behavior changed.
