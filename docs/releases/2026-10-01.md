# October 1, 2026 — Observability updates and Forwarder provenance repair

## Plain-language summary

Version Compass now includes two September 23 Observability Cloud service changes that were added to Splunk's September timeline after the previous review: quieter Kubernetes Autodetect definitions and Detector Optimization in Controlled Availability. Detector recommendations remain customer-reviewed and are not applied automatically.

The customer-managed component guidance also adds Splunk OpenTelemetry Node.js 4.12.0 and Java 2.31.3. The Node.js release updates its OpenTelemetry dependencies, adds Couchbase SDK 4.7-or-later and vendored MySQL2 instrumentation, migrates the tracing package, and avoids failing installation when a native extension has no prebuilt binary. Java 2.31.3 is explicitly a re-release of 2.31.2: it retains the remote CPU-profiling control fix and repairs Docker image publishing.

The Forwarder source-register generator has also been repaired. Universal Forwarder, Heavy Forwarder, receiver, intermediate-topology, certificate, maintenance and security claims now use a stable claim registry, and the generated register retains each exact claim path and supporting source section. This is a provenance repair, not a new compatibility or authorization claim.

## Affected products and routes

- **Observability Cloud, July 2026 to September 2026:** four new feature records, two before/after technical records and three scoped requirements appear in the existing compact report. Rolling SaaS changes remain distinct from customer-managed instrumentation versions.
- **Splunk Forwarders:** no route, version, receiver, OS, topology or authorization fact changed. The generated source register can now demonstrate which exact section supports each maintained UF/HF claim.
- **Splunk Enterprise, Cloud Platform, Enterprise-to-Cloud migration, Enterprise Security and ITSI:** no route or compatibility change. Enterprise 10.4.4 remains the current 10.4 maintenance target; the Cloud service pairing remains Cloud 10.5, ES 8.6 and ITSI 5.0.
- **ES Editions and Cloud Environments:** no factual update. Edition, entitlement, provider, region and FedRAMP claims remain owned by their dedicated evidence sets.

## Customer-facing impact

Observability customers can see the new service behavior and exact component boundaries without treating a Controlled Availability recommendation service as automatic remediation. Node.js and Java users receive concrete dependency, database-instrumentation, packaging and validation requirements rather than a generic "upgrade the agent" instruction.

Forwarder readers see no additional interface or disclosure burden. The source compendium and generated provenance data become more reliable while the route-first screen, compact decision summaries, top-bar actions, sharing, print, saved HTML and read-only WebMCP behavior remain unchanged.

The material-content cycle advances once for this factual batch. Existing cycle-three Enterprise maintenance guidance remains marked for one more material cycle; older badges expire without deleting their underlying facts or history.
