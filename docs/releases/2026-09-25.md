# September 25, 2026 — Browser RUM 3.2 guidance

Splunk published Browser RUM 3.2.0 on September 24. Version Compass now identifies 3.2 as the current Browser RUM component in the September 2026 Observability route while retaining the separately documented 3.1 default-change baseline.

## Customer-facing changes

- Browser RUM 3.2 adds manual page-load registration so applications can include important work that ordinary network and resource monitoring cannot detect in Page Completion Time.
- Optional blocking-element instrumentation can report configured elements that delay a page or route from appearing complete.
- Resource spans can now retain an exposed failed HTTP status and error state independently of resource-load client-error reporting.
- The `spaMetrics` configuration key is renamed to `navigationMetrics`. Existing `spaMetrics` configuration remains functional as a deprecated alias, so 3.2 does not impose a mandatory code or configuration migration.

## Compatibility, readiness, and breaking-change implications

The affected route is Splunk Observability Cloud ending at `Sep 2026`, in either connected Enterprise or Cloud Platform context. Version Compass adds a cited before-and-after configuration record and a non-breaking planning action: use `navigationMetrics` for new work and migrate maintained templates during the normal rollout. Teams adopting manual page-load registration should validate the documented 180-second default maximum wait against their application behavior.

Browser RUM 3.1's frustration-signal, Page Completion Time quiet-window, and failed Session Replay storage changes remain separately visible because customers moving from an older agent still cross that baseline. No Splunk Enterprise, Cloud Platform, Enterprise-to-Cloud, Enterprise Security, ITSI, SCMA, lifecycle-policy, compatibility-gate, ES Editions, environment-evidence, or WebMCP schema change is required.
