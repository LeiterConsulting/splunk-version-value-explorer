# September 16, 2026

## Summary

Version Compass expanded its September 2026 Observability guidance with current customer-managed OpenTelemetry component changes and added an explicit security-fix floor for Splunk Enterprise Security 8.6.

## What changed

### Observability Cloud and OpenTelemetry

- Added Splunk OpenTelemetry Collector 0.160.1 and Kubernetes chart 0.160.0 to the September 2026 milestone.
- Added route-specific blockers and actions for the Collector 0.160 line:
  - migrate Linux auto-instrumentation configuration from the legacy Splunk path to the OpenTelemetry injector path;
  - replace the removed `scripted_inputs` receiver with the documented `splunk_inputs` path;
  - remove `deployment_name_from_replicaset`, which can prevent Collector startup;
  - validate changed Linux log sourcetype defaults.
- Added Node.js instrumentation 4.11.0 guidance for stable HTTP and database semantic-convention attribute names.
- Added Browser RUM 3.1 guidance for changed frustration-signal, page-completion, and failed-replay storage defaults.
- Added the Collector lookup processor and Browser RUM 3.1 as customer-value capabilities while keeping rolling SaaS availability separate from customer-managed component versions.

### Enterprise Security

- Added a required Enterprise Security 8.6.1-or-later security floor.
- Added the corresponding blocker and action for deployments on affected 8.6 maintenance levels, based on Splunk advisory SVD-2026-0807.

### Review metadata

- Updated the on-site and printable-report review date to September 16, 2026.
- No journey, selector, sharing, or print interaction was changed by this content update.

## Why it matters

Customers evaluating the September 2026 Observability milestone now see concrete pre-upgrade work that could otherwise interrupt telemetry collection, alter downstream content, or change browser instrumentation behavior. Enterprise Security readers are no longer left with an undifferentiated “8.6” target when a fixed maintenance release is required.
