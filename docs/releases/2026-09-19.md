# September 19, 2026

## Summary

Version Compass added Splunk OpenTelemetry Collector 0.161.0, published September 18, 2026. The Observability route now identifies its customer-actionable Kubernetes semantic-convention, CPU-metric, Google Cloud audit-log, SQL Server attribute-scope, and custom-extension changes while keeping the standalone Collector distinct from Kubernetes chart 0.160.0.

The header's reviewed-date block now links directly to this release note, so the displayed review date and its evidence record advance together.

## What changed

### Splunk OpenTelemetry Collector 0.161.0

- Added the stable `k8s.pod.label.*` convention and documented that legacy `k8s.pod.labels.*` attributes are disabled by default, including Splunk's dual-emission migration option.
- Added the default kubelet CPU calculation change from `UsageNanoCores` to rates derived from cumulative `cpu.time`, including the missing first scrape after startup.
- Added the Google Cloud audit-log RPC semantic-convention change and the move of SQL Server endpoint fields from top-query log attributes to resource attributes.
- Scoped the removed `pkg/service` `ZapOptions` API to custom Collector builds and extensions rather than ordinary packaged-distribution configuration.
- Added the Splunk-specific hot-reload and independent TA input-reconciliation improvements as operational capabilities.

### Component boundary and review link

- Kept Kubernetes chart 0.160.0 paired with Collector 0.160.1. Version Compass does not imply that chart users automatically receive standalone Collector 0.161 behavior.
- Advanced the reviewed date to September 19, 2026 and linked it to this dated note.

### WebMCP agent access

- Added read-only tools to discover products/releases, compare one to five routes, and retrieve the current report in a WebMCP-capable browser.
- Shared the existing comparison engine between the page and tools, including official citations, compatibility gates, technical changes, breaking risks, readiness work, review metadata, and report URLs.
- Added strict input validation, optional result sections, unsupported-browser fallback, registration cleanup, and a dependency-free contract harness.
- Extended maintenance guidance and scheduled audits to cover the agent contract and UI/tool parity.
- Allowed the newest Enterprise release as a migration source. Missing Enterprise graph paths now remain unknown rather than appearing to be direct upgrades.
- Documented that browser-scoped WebMCP does not provide a standalone HTTP MCP endpoint.

### Footer discovery

- Added a compact “For AI agents” footer note describing read-only WebMCP access for compatible browser-based agents, with an inline link to the agent-access documentation.
- Reused the existing footer typography and green link accent, with hover and keyboard-focus states. The link wraps naturally on narrow screens.
- Verified the footer markup, documentation destination, and focused style changes. No comparison logic changed.

## Customer-facing impact

Standalone Collector users can now assess 0.161 directly. Kubernetes users should migrate dependent content to stable label attributes, rebaseline CPU series and detectors, and update SQL Server field access before production rollout where those components are used. Chart users remain on the chart's documented 0.160.1 Collector baseline unless they deliberately override the image or Splunk publishes a later chart.

## Compatibility, readiness, and breaking-change implications

- Kubernetes label attributes and kubelet CPU calculations change by default in Collector 0.161; both are flagged as potential breaking changes.
- SQL Server `server.address` and `server.port` change attribute scope for `db.server.top_query` and require content review.
- Google Cloud audit-log RPC changes apply only when that extension and the retired attribute names are in use.
- The removed `ZapOptions` API applies to custom Collector code, not normal YAML configuration of Splunk's packaged distribution.
- No new Kubernetes chart, Splunk Enterprise, Splunk Cloud Platform, Enterprise Security, ITSI, Cloud Migration Assessment App, or Observability SaaS milestone was published in this review.

Agent users can query the same curated information without scraping cards or changing the visitor's current selection. No data collection, registration, or new primary-page controls were added.
