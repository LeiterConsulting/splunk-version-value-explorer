# Advisor requirement workflow

This candidate changes `/?view=advisor` to a blank requirement-response workflow
inside the existing navigation. It retains the guided decision engine as assessed
shared facts and a bounded compatibility reader. Implementation is not a live
release; see [release and rollback](advisor-workflow-release.md).

## Brief creation and trust

Visitors add original statements, then author and accept separate atomic criteria.
Original wording is preserved separately from interpretations, mappings and review.
Composite requirements require decomposition. Fit, evidence health, product scope,
prerequisites and entitlement remain separate dimensions. A documented minimum is
not full compatibility, tenant access or a license promise. Unknown, contradictory,
withdrawn, expired or branch-mismatched evidence fails closed in its actual scope;
an independently established numeric comparison can retain its bounded result.

Canonical public facts come from `content/datasets/guidance.json`, the existing
Advisor admission model and the scoped typed prerequisites under
`tools/advisor-workflow/shared`. Sources retain retrieval status, assessed scope,
claim dates and review windows. The November 9 reconciliation admits only its
documented sections. Indexed evidence is labeled; direct-page retrieval was
blocked for those sections. The unavailable CMP setup source retains November 4
dates and unresolved status. Earlier indexed responses cannot all be reconstructed;
no raw-page freshness is asserted. Build times never refresh factual dates.

Local imports are inert JSON/text, not instructions or executable evidence.
Imported mappings and acceptance require review. No PDF/OCR extraction, natural
language mapping, remote inference or API credentials are provided. Vendor claims,
customer notes and imported material do not become canonical public facts.

## Navigation and compatibility

Current public goal links retain their decision and self-reported context model.
Legacy `itsi-assistant`, `ingest-pressure` and `stay` preserve original intent and
explain limits; the ITSI dependency decision needs an explicit transition.
Unsupported, duplicate or ambiguous URL inputs block assessment and export while
retaining the input for inspection. Explicit recovery starts blank. Old section
anchors map to corresponding sections without rewriting the fragment.

History contains public goal/theme/section intent and opaque per-tab draft refs.
Private notes, requirements, aliases and version reports are never placed in URLs
or history state. Back/forward suspends an unfinished editor with its owning draft
object; save/cancel verifies ownership. Equal imported IDs remain separate in-memory
identities. There is no autosave: reload starts blank, and cross-page navigation
requires a deliberate private save for guaranteed recovery. A browser back cache
is not persistent storage.

Existing device profiles retain their origin-local key. Loading requires a preview,
preserves original self-reports, resets imported acceptance and flags unsupported
values. Another origin's profile must be explicitly imported. Decision links share
public intent only. The same-origin, one-use ten-minute Agent Mode Guide note stays
in session storage; the Guide opens separately with its opener detached and without
installed/target versions in its URL. Closing it returns to the retained brief.
A blocked popup leaves the brief intact and clears the note. It never chooses
comparison values for the visitor.

`advisor-guided.html?view=advisor` temporarily exposes the guided comparison on
the same current facts. It is not itself a rollback of the default route.

## Host evidence, private files and exports

The native route keeps host canonical globals and revision, comparing the declared
AI/exact-release/source/provider/region dependencies. A changed, missing or withdrawn
relevant host fact blocks evaluation/export; embedded older support cannot replace
it. Unrelated host content is retained without unnecessarily pausing this scope.
Missing host delivery blocks the native workflow and offers a separate explicitly
pinned standalone blank file. Captured/offline files remain dated snapshots.

The compiler produces `dist/advisor-workflow.js`, the blank self-contained
`dist/advisor-workflow-candidate.html`, and the guided comparison shell. It rejects
private document/example inputs. The distributed entry contains no private brief or
trial. Customer context stays in browser memory or deliberate origin-local profile
storage; application actions do not transmit it. No telemetry is added. Public
canonical loading and private imports are distinct trust boundaries.

Editable workspace exports deliberately contain selected private input/history and
executable public workflow code. Neutral report HTML is script-free. Screen, native
PDF and offline reports retain the same criteria, citations, blockers and caveats.
Export is blocked for missing, incomplete or stale captured assessments. Audit
digests check consistency, not signatures or source authority. Users must choose
what private files to share; publishing a saved workspace would disclose its input.

The public-oriented package contains only blank workflow code, public canonical
evidence and explicitly synthetic tests. Private source documents, trial briefs,
customer imports and their audit histories are excluded. Any public demo
requires a separate content/privacy review.

## Maintenance scope

The draft coverage amendment under `tools/advisor-workflow/proposals` is inactive
against registry 1.2.0. Implementation does not change saved tasks or schedules.
Validated saved configurations and an actual participating run are required before
claiming amended scheduled responsibility. The existing watches and fail-closed
review windows remain authoritative. Full independent active delivery and a real
customer trial are not prerequisites for engineering review. Spoken VoiceOver is
outside the acceptance scope.
