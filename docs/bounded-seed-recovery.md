# Manual bounded seed preparation (proposed, not activated)

`recover-seed-only` is a single manual job under the existing publisher concurrency group. It reuses existing authenticated `resumeSeed` (maximum 50 immutable rows per call) and `observeSeed` (separate metadata/count readback). No endpoint, permission, credential scope, automatic schedule, default publishing or runtime flag changes are added. It cannot bootstrap, stage provenance, or move a head.

Supply the exact reviewed main commit/ref, deployed seed source commit, engine and revision, and an explicit starting count/batch budget. Defaults of 50 and 19 describe the reviewed November14 partial recovery, not a reusable assertion about current state. The first independent observation must match that count and show absent head or there are zero writes. Each batch must advance exactly min(50, remaining); all identity and count checks must match, the head must remain absent, and the final batch must report all-rows-exact. A separate observation after every batch confirms counts, not independently verified record bytes.

Maximum20 batches per approved dispatch,15-minute cooperative deadline plus existing fixed per-request deadlines. Only run attempt1 is allowed; GitHub reruns are rejected. No automated retries. On any error, no-progress, changed head/identity/count, timeout, receipt retention failure or cancellation, stop and reconcile the original attempt. A fresh dispatch requires newly reviewed starting state and remaining authorization; it must not silently replenish the batch budget. Completed batches do not imply an uncertain in-flight batch failed.

Inputs are loaded and validated once from a clean checkout before any output. Per-call receipts and SHA256 index files are written exclusively under runner.temp/vc-seed-recovery, outside the checkout, and uploaded even when the job fails. Each filename is write-once. Existing clean-checkout gates remain intact. Credentials are handled only by existing callers and never retained in receipts. There is no explicit cleanup of useful failed-run evidence.

The successful outcome is `prepared-not-published`. It means server-reported exact rows plus separately observed matching count and no head. It is not independent full-row byte verification, factual currency, readiness, activation eligibility, delivery or operational completion. Download original artifact and verify GitHub digest, exact run/attempt/main and every indexed receipt externally. Bootstrap remains a separate, qualified production cutover because the reader may already be enabled even while publisher activation is0. Verify rollback, quiescence, live source/env and current main again before that action; restore workflow disabled after recovery.

This implementation must receive independent review, exact-final-head CI/export evidence and explicit integration/dispatch authorization before use. Do not treat this file or a green local test as activation.
