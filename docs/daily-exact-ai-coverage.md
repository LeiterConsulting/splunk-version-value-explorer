## Required daily evidence

Record each assigned capability in the normal versioned coverage receipt. Exact Releases covers release identity and ordered branches, feature and documentation changes, the bounded advisory scope, the UF receiver acknowledgement regression and fix, and conflict/uncertainty parity. AI Availability covers all ten named capability records and the distinct discovery, provider, service-location and regional scopes. Update the registry alongside any intentional addition to the bounded claim or capability inventories.

Name the real saved-task and scheduler run, exact claim scope, official source sections, retrieval evidence and assessment times. Use the existing dispositions, including `assessed-no-change` after an actual scoped assessment and `deferred`, `blocked` or `failed` with an owner, next step and review date for a gap. Reuse a current source read where it actually supports that section. Maintain separate retrieval and assessment clocks and preserve historical evidence dates. A failed or partial watch can still describe useful bounded work. Its outstanding capability remains visible in the daily rollup. All four source watches can bind their own audit with `scripts/record-automation-coverage.cjs` using the current registry.

The noon audit uses the local Eastern date and the most recent matching completed scheduler attempt for each due watch. Exact Releases has a same-day source assessment only when its five Release Watch dispositions are complete. AI Availability has a same-day source assessment only when all seven primary scopes across Release, ES and CSP are complete. List missing receipts, incomplete scope and late work explicitly. Guidance provides independent review when due. Track GitHub integration, exact-head CI, the steward's selected package and public readback as separate stages. A late receipt can be reconciled next time without rewriting its original timestamps.
