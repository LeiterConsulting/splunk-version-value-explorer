# Proposed constitution amendment: exact-release pilot

Draft amendment `exact-release-graph-20261102`, intended registry version 1.1.0.
This supplements the evidence, privacy and truthful-outcome rules of
[constitution 1.0.0](automation-constitution.md). It is prepared for review, not
activated and not evidence that any saved task was changed or ran.

Owner approval covers this bounded build and validation. Publication, broader
historical coverage and operational activation remain separate decisions.

The proposed mandatory families are exact release identity/ordering, capability
history and documentation corrections, one SVD-2026-1007 CVE's branch remediation,
the component-scoped UF useAck regression, and evidence conflicts/unknowns with
screen/tool/export parity. Details live in the machine-readable
[proposal](../content/exact-release-coverage-proposal.json). Existing Release Watch
owns the data; existing Guidance Audit independently checks every family. The
other watches retain their existing product/edition/regional responsibilities.

Every participating run must explicitly declare changed, assessed-no-change,
deferred, blocked, failed or out-of-scope for every family after activation, naming
the public sections, exact claim IDs and component/branch scope actually assessed.
Retrieval is not assessment. Ordering is not inheritance. A fixed endpoint is not
an overall security assessment. Existing assessments/history and unresolved
contradictions remain intact. Never refresh verification dates through a build,
UI change, reused source read or downstream inheritance.

Impact: one optional exact-release view and one additive read-only WebMCP tool;
PDF/offline HTML and shared/invalid/mobile routes are included. Existing line
URLs, tool names, meaning and complete content delivery stay intact. No customer
data collection, new service, database, endpoint, timer or cap increase. Reuse
existing watches and the existing progress task; no saved settings are mutated by
this proposal. Cost, tokens and measured elapsed time remain null unless measured.

Activation requires a reconciled current repository/coverage amendment, exact saved
task IDs with before/after configuration and independent readback preserving
schedules, timezones, enabled state and permissions, plus a real executed and
verified run for each affected task. The open maintenance draft's readback and
first-run state must be reconciled rather than overwritten or assumed complete.
Local unit tests, a manual source review, a draft PR and CI exports do not satisfy
those operational requirements. Review effort/value through the existing Guidance
Audit after four actual complete cycles; keep incomplete work explicitly deferred.
